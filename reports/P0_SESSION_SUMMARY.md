## 2. 正面结论（可以往论文里写）

### 2.1 存在性检测不是「对角度取最大」抬出来的

`max_γ S(γ)` 确实把 null 分数抬高了 1.57–2.46 倍（搜索增益），
但阈值是在**同一统计量、互不相交**的校准划分上标定的，因此：

| 指标 | 结果 |
|---|---|
| TPR@1%FPR（8 格） | 7 格 **1.000**，1 格 0.800（rot+noise） |
| AUC（8 格） | 7 格 **1.000**，1 格 0.962 |
| 实测 FPR | 0.00–0.06（Wilson 上界 0.07–0.16） |
| **同一名义 FPR 下「关闭搜索」的 TPR** | rot45 **0.020**、rot75 **0.260**、rot+noise **0.100** |

最后一行是关键因果证据：**同一批水印图、同一个目标 FPR，只切换解码端是否搜索角度**，
旋转下的 TPR 从 1.000 掉到 0.02–0.26。这直接回答「你的 AUC 是不是 max-over-angles 抬出来的」。

校准/测试的可交换性也做了检验：AUC(测试 null vs 校准 null) = 0.406–0.569，
均值比 0.90–1.04，**不存在「测试划分更难」的系统偏置**。

### 2.2 纯旋转已经解决

三组独立扫描合计 **1230 个纯旋转样本，失锁 5 个（0.41%，Wilson 95% CI [0.17%, 0.95%]）**：

| 组 | n | 失锁率 [95% Wilson] | 角误差 中位/p90 | BitAcc | oracle BitAcc |
|---|---:|---|---:|---:|---:|
| grid（15° 步长） | 720 | 0.0042 [0.001, 0.012] | 0.00 / 0.00 | 0.9946 | 0.9976 |
| fixed（非格点+负角） | 270 | **0.0000** [0.000, 0.014] | 0.30 / 0.50 | 0.9995 | 0.9995 |
| random（连续随机角） | 240 | 0.0083 [0.002, 0.030] | 0.27 / 0.64 | 0.9906 | 0.9969 |

* **负角无偏置**：σ=0 时负角 0/90、正角 0/180。
* **非格点角不是问题**：误差 p90 = 0.50°，正好是 1° 搜索网格的半步长；盲解码 = oracle 解码。

### 2.3 旋转鲁棒性不是某个 `rotate()` 实现的性质

**攻击端换成 4 种训练时未见的实现**，在 canonical 解码下：

| 攻击算子 | 失锁率 | BitAcc | PMR |
|---|---:|---:|---:|
| `pil_bilinear`（此前一直用，参考） | 0.000 | 0.9958 | 0.967 |
| `pil_bicubic` | 0.000 | 0.9938 | 0.950 |
| **`pil_expand_crop`（去掉零填充楔形、不变尺度）** | **0.000** | **0.9958** | **0.967** |
| `cv2_linear_reflect`（OpenCV 线性 + reflect 填充） | 0.033 | 0.9771 | 0.900 |
| `cv2_cubic_constant`（OpenCV cubic + 常值填充） | 0.000 | 0.9938 | 0.950 |

`pil_expand_crop` 与参考格**逐位相同** ⇒ **同步没有读黑边**。
**解码端换成 bilinear / bicubic** 同样无损失（bicubic 甚至略好，PMR 0.970 vs 0.947）。
唯一系统性退化来自**把旋转中心挪到 DFT 原点**（BitAcc 0.919、PMR 0.723、失锁 0.070），
与命题 3 的半像素几何预测一致。

### 2.4 质量—鲁棒权衡：等质量下 B8 明显优于 B16

| 比较（质量几乎相同，B16 略优） | PSNR/SSIM/LPIPS/CLIP | rot45 PMR | rot+noise PMR |
|---|---|---:|---:|
| η=5e3：B8 vs B16 | 14.78/0.520/0.408/0.324 vs 14.97/0.534/0.393/0.333 | **0.820 vs 0.240** | **0.700 vs 0.340** |
| η=1e4：B8 vs B16 | 12.10/0.394/0.569/0.317 vs 12.43/0.409/0.548/0.319 | **0.960 vs 0.580** | **0.880 vs 0.580** |

主配置 **B8 / η=1e4** 的 CLIP 配对差只有 **−0.0148**（近乎不可察觉），
而 rot45/rot+noise PMR 仍为 **0.960/0.880**。
另外，本轮 B8/B16 在 η=1e4 的数值与草稿 §5.9.1/§5.9.4 **逐项一致**，属独立复现。

## 3. 必须处理的负面结果：`S(γ)` 不是密钥归属统计量

**证据（controls）**：用错密钥解码的水印图，在 null 标定的存在性阈值下 FPR：

| 攻击 | key s1 | key s2 | key s3 | AUC(wm vs wrong-key) |
|---|---:|---:|---:|---:|
| clean / JPEG / 噪声 | **1.000** | **1.000** | **1.000** | 1.000 |
| 模糊 r=5 | 0.880 | 0.900 | 0.980 | 1.000 |
| 亮度 ×6 | **1.000** | **1.000** | **1.000** | 0.987–0.990 |
| 旋转 45° / 75° | 0.160–0.280 / 0.780–0.840 | | | 0.997–1.000 |
| 旋转+噪声 | 0.240–0.280 | | | 0.851–0.860 |

**机制**：`S(γ)=∏_l mean_j|ℓ_j|` 度量「环带能量在载波方向上的投影幅度」，
而错误码本张在**同一条环带**上，key-A 的水印能量必然大量漏进 key-B 的载波方向。
所以它对「有没有水印」很敏感，对「是不是我的 key」不敏感。

**处方（建议直接写进口径声明）**：

1. `S(γ)` 只作**存在性**统计量，负样本 = 无水印图（此路已通过闸门）；
2. 密钥归属用 **payload**（bit 全对率 / PMR），与草稿既有的「bit 载荷 vs key 空间」口径一致；
3. **不要**把「key-aware 阈值 + S(γ)」包装成新组件——实测它虽然在 7/8 格把错密钥
   FPR 压到 ≤0.007，但 **rot+noise 的 TPR 会从 0.800 崩到 0.220**（水印分数均值
   16615 < 错密钥阈值 19935），说明该统计量在组合攻击下不具备足够区分度。

## 4. 机制：几何攻击是「引入同向残差」，不是「擦掉水印」

`E(ω)=R_{−α}Ẑ_T(ω)−Z_w(ω)`（oracle 对齐后）：

| 条件 | 衰减 dB | ‖E‖² | 层0/层1 SNR | 残差落在载波子空间的比例 |
|---|---:|---:|---|---|
| clean | −2.12 | 1.73e3 | 307.3 / 452.9 | 0.511 / 0.450 |
| rot45 | −3.71 | 1.13e4 | **6.63 / 2.12** | **0.621 / 0.674** |
| rot75 | −3.92 | 1.00e4 | 11.07 / 5.62 | 0.617 / 0.670 |
| noise0.05 | −2.53 | 3.46e3 | 121.5 / 146.2 | 0.489 / 0.445 |
| rot+noise0.05 | −4.24 | 1.04e4 | 10.18 / 4.78 | **0.642 / 0.699** |

三条可写进论文的机制结论：

1. **环带能量基本保留**（衰减只有 2.1→4.2 dB），残差涨了 6 倍 ⇒ 不是「被擦掉」；
2. **残差 62–70% 落在载波子空间内**（clean 只有 51%）⇒ 攻击更像一个**载波同向的偏置**，
   这解释了为什么假峰也会被抬起来；
3. **rot+noise 的特征是相对裕度塌陷**：`Δrel` 从纯旋转的 0.784 掉到 **0.528**
   （`S_true` 与 `S_false` 都回升，后者回升更多），而不是「真峰再塌一次」。
4. 附带设计线索：**外层（K=36）SNR 总是低于内层（K=32）约 2–3 倍**，
   product 融合因此由较弱的外层决定。

## 5. 身份识别（ours）

**第一版结果作废**：冒烟（2-key 注册表）与全量（20-key）写进了同一个 `out_dir`，
`ResumeLog` 按 uid 去重导致 4 张图保留了冒烟的 2-key 记录（注册表大小在样本间不一致）。
污染目录已改名为 `runs/identity_ours_CONTAMINATED_mix`，**结论以重跑为准**：

**重跑（`runs/identity_ours_n20`，360 行全部 `n_keys_registered = 20`，rc=0）**：

| 攻击 | Id-Acc@1 [95%CI] | AUC(注册 vs 无水印) | TPR@1%FPR | FPR(null) | AUC(注册 vs **未注册**) | FPR(**未注册**) |
|---|---|---:|---:|---:|---:|---:|
| clean | **1.000** [0.839, 1.000] | 1.000 | 1.000 | 0.000 | 0.917 | **0.500** |
| rot45 | **1.000** [0.839, 1.000] | 0.990 | 0.950 | 0.000 | 0.905 | 0.300 |
| rot75 | **1.000** [0.839, 1.000] | 1.000 | 1.000 | 0.000 | 0.868 | **0.700** |

* **正面**：闭集身份识别在 clean/rot45/rot75 上都是 1.000，是「旋转下几乎无损失」的完整性证据；
* **负面**：换成**未注册 key** 这个更难的负样本后，存在性阈值下 FPR 高达 0.30–0.70 —— 
  与 §3 的错密钥结论同源，**身份表必须用未注册 key 标定阈值**；
* 口径：ours 的身份 = payload 精确匹配，因此 **Id-Acc 本质等于 PMR**，不是独立能力；
  key 空间 256（=2^8）与注册量 20 是两个不同的数（详见 `P0_identity_report.md`）。

## 7. 本轮踩到并修掉的坑（复现时注意）

1. **`SplitPlan` 默认 `test_offset=1000` 越界**：本实例 `meta_data.json` 只有 1000 条 caption
   （`images512` 有 5000 张图），直接跑会 `IndexError`。
   本批统一显式传 `--calib_offset 0 --test_offset 500`。
2. **`run_inversion_error_spectrum.profile_arrays` 维度 bug**：把二维掩码用于索引一维数组，
   必然崩。已修（在掩码域内选择）。
3. **LPIPS 设备不匹配**：`run_capacity_quality_pareto.quality_metrics` 与
   `run_quality_gt.distortion` 把 CPU 张量喂给 CUDA 的 LPIPS。已修两处。
4. **`run_unseen_operators.py` 新写时要小心的四个约定**：
   `TF.affine` 的正角方向与 `TF.rotate` 相反；torchvision 用的是自己的 `_gen_affine_grid`
   而不是 `F.affine_grid`；PIL 的 `center` 相对像素索引偏移 +0.5；潜变量是 fp16 而 grid 必须同 dtype。
   脚本现在会在启动时自检（解码圆盘内偏差 <1e-4 才继续）。
5. **`ResumeLog` 的 uid 去重会把冒烟结果留下来**：下一次跑大 N 时那些 uid 会被跳过，
   于是同一次「运行」里混进不同配置的行。**冒烟与正式跑必须用不同 `out_dir`**（本轮 identity 因此重跑）。
6. **`run_p0_queue.sh` 的 `*_done.txt` 不检查 rc**：pareto 第一次失败也写了 `p0_pareto_done.txt`。
   不要用 marker 判断成功，要看日志里的 `(rc=…)`。
