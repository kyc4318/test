## 0. 一句话

**质量问题上投影法几乎完全解决（PSNR +15 dB、LPIPS 0.59→0.10），但它在
「真角上 payload 可读（oracle BitAcc 0.95–1.00）」的同时，让**角度搜索**失效
（clean 就失锁 80%）——失败在同步，不在载荷。**

## 1. 质量：决定性改善

| arm | 潜变量 RMSE | 载波内占比 | **正交补占比** | PSNR ↑ | SSIM ↑ | LPIPS ↓ |
|---|---:|---:|---:|---:|---:|---:|
| `replace:1e4`（canonical） | 0.4442 | 0.7150 | **0.2850** | 11.93 | 0.3997 | 0.5899 |
| `project:0` | 0.0411 | 1.0000 | **0.0000** | **26.94** | **0.8761** | **0.1036** |
| `project:20` | 0.0413 | 1.0000 | 0.0000 | 26.94 | 0.8754 | 0.1043 |
| `project:40` | 0.0428 | 1.0000 | 0.0000 | 26.83 | 0.8709 | 0.1072 |
| `project:80` | 0.0512 | 1.0000 | 0.0000 | 25.16 | 0.8419 | 0.1325 |

* PSNR **11.93 → 26.94 dB**（+15 dB），LPIPS **0.590 → 0.104**（−82%），
  SSIM 0.40 → 0.88。逐样本更极端（例如 sample 1：12.3 → 36.8 dB）。
* 结构证明：投影法的正交补占比是 **0.0000**（host 的正交补**一个点都没动**），
  而 replace 有 **28.5%** 的扰动砸在 host 原本占用的方向上——这正是画面出现
  规则纹理的来源。
* CPU 自检（`--selfcheck`）还确认投影法的 **clean BitAcc = 1.0000**
  （在未经过 diffusion 的潜变量上），即 payload 确实写进去了。

**结论：方案对质量问题的诊断是对的，投影 embedding 是有效的修复。**

## 3. 诊断：失败在同步，不在载荷

**oracle BitAcc**（用真实角度解码，绕过搜索）：

| arm | clean | rot45 | rot75 | rot+noise0.05 |
|---|---:|---:|---:|---:|
| `replace:1e4` | 1.000 | 1.000 | 0.994 | 0.956 |
| `project:0` | **0.950** | 0.600 | 0.575 | 0.562 |
| `project:40` | **0.988** | 0.625 | 0.581 | 0.569 |
| `project:80` | **1.000** | 0.644 | 0.631 | 0.613 |

读法：

1. **clean 的真角解码是可用的**（0.95–1.00）→ 投影 embedding 把 payload 写对了，
   也穿过了 generation→inversion；**问题不在 embedding 本身**。
2. 但 **blind（要搜角度）clean 只有 0.53** → **同步器找不到那个角**。
3. 机制：同步分数 `Π_l mean_j|ℓ_j|` 度量的是「载波方向上的能量」。
   replace 把环带重写成 ℓ_j ≈ ±100 的结构化图案，远超 host 内容
   （|Z|≈64）与反演残差，所以峰清晰；投影法把每个 bit 的幅度钉在
   **host 自身的投影幅度 |a_j| ≈ 37**（实测），与内容 nuisance 同量级
   → 景观峰被内容淹没，**不需要攻击就已经失效**。
4. 这与项目早先的「同步是检测问题、margin ∝ √η、同步瀑布」结论完全一致：
   **同步的可分辨性来自水印幅度，而 host-preserving 恰恰意味着把幅度压回 host 量级。**

## 4. 因此第一步和第二步是耦合的（方案顺序需要调整）

原方案把「改 embedding」与「改同步 score」当作先后两步。实测表明：
**只要幅度降到 host 量级，旧的 `Π mean|ℓ|` 统计量就不再可用**，
所以必须同时换一个能抵消内容 nuisance 的同步统计量。

而方案的第二步（**shared-payload signed score**）恰好具备这个性质：
两个层位于**不同径向带**，内容 nuisance 近似独立；而 payload 在真角上
是**共享符号**。于是

```text
S_shared(γ) = Σ_j | ℓ_{1j}(γ) + ℓ_{2j}(γ) |
```

在真角上建设性叠加、在假角/错 key 上相互抵消——这正是低幅度下重建峰值所需要的。
也就是说：**投影 embedding 要活，必须配 shared-payload 同步统计量**，
两者应当合并成一次实验，而不是顺序各做一遍。

## 5. 建议的下一步（按此顺序）

1. **扩展 τ 到 {100, 150, 200, 300}**：τ→∞ 时「投影+地板」退化为
   「host + 加性结构化水印」，是 replace 与 project 之间的连续插值。
   目标是在质量仍 ≥18–22 dB 的区间找到「旋转可用」的工作点。
2. **实现 shared-payload 同步统计量**（独立脚本，不改 `swm/`），
   在 τ=0/40/80 上测 clean/rot45/rot75/rot+noise 的失锁率。
   验收：把低 τ 的失锁率从 80–95% 压回 <5%，则「质量 26.9 dB + 旋转可用」同时成立。
3. 只有 1+2 都不行，才回到「接受 replace 的质量代价」或考虑
   「用冗余维度换鲁棒性」（方案第 7 条：每 bit 用 2 个正交载波重复）。
