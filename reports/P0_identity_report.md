# P0 身份识别（ours 进入 key 任务）

**状态**：已跑完（RTX 4090D，2026-09-20，rc=0，用时 13.6 min）。
**脚本**：`run_identity_benchmark.py`。
**数据**：`runs/identity_ours_n20/{rows.jsonl,summary.json,ours_meta.json}`（360 行）。

> ## ⚠️ 更正（2026-09-21）：身份判决用的是 **payload 匹配 margin**，不是 `S(γ)`
>
> 本报告初版把 identity 的未注册误接受与 controls 的错密钥高分称为「同源」，
> 并在 §3.2 把原因归于 `mean|ℓ|` 类分数。**这两处不准确。**
>
> 读 `run_identity_benchmark.py::OursIdentity.decode` 可见，身份判决**根本不使用
> `S(γ)`**：它先用角度搜索得到软比特 `ℓ`，再对每个注册 payload 算相关系数
> `q_k = (1/B) b_kᵀℓ`，取 `q` 最大的注册身份，并以
> **`margin = q_best − q_second`** 作为校准统计量（另有一条按汉明距离取最近的
> `hard` 路径，两条都记录在 `pred_id_soft` / `pred_id_hard`）。
>
> 因此应当分开表述：
>
> * **controls 的错密钥高分**：说明**存在性统计量 `S(γ)`** 不能认证秘密载波；
> * **identity 的未注册误接受**：说明**基于已注册 payload 的匹配 margin** 尚不能
>   可靠拒绝未注册 payload。
>
> 两者的**处方形状**相同（都要把「更难的那类负样本」——错密钥/未注册——拿来做
> 阈值标定，而不是用无水印图），但**机制与统计量不同**，不能写成同一个结论。
> 一个具体例子：注册了 `10110010` 与 `10110011`、未注册的是 `10110000` 时，
> 后者与第一个注册码字仍然高度相似——即使「有没有水印」毫无疑问，
> 系统也必须判断它**不属于注册表**。
>
> **另外**：本报告初版说「ours 的身份 = payload 精确匹配，因此 Id-Acc 本质等于
> PMR」。这也太强。闭集 Id-Acc 只要求**正确身份的得分最高**：
> 8 bit 里错 1 位时 PMR=0，但只要「错位后的邻居码字」没有被注册，
> Id-Acc 仍可为 1。所以两者**可以有相同数值，但判定规则不同**，
> 不能互相换算，也不应写成同一个指标。
>
> **正确表述**：「**闭集识别表现良好**（Id-Acc@1 = 1.000），
> **开放集拒绝仍待验证**（未注册 payload 的误接受在当前阈值下为 0.30–0.70）」。

## 0. 一句话结论

**正面**：闭集身份识别 **Id-Acc@1 = 1.000**（clean / rot45 / rot75 三格全部），
「注册身份 vs 无水印」的 AUC 0.990–1.000、TPR@1%FPR 0.950–1.000、实测 FPR 0.000。
**这是本轮唯一一处「旋转下几乎没有损失」的完整性证据**（rot75 仍 1.000）。

**负面**：把负样本换成**未注册 key 的水印图**（更难、也是更该报的那一类）后，
AUC 掉到 0.868–0.917，在 null 标定的阈值上 **FPR 高达 0.30–0.70**。
与 controls 的错密钥结果同源：**分数度量「有没有水印」，不度量「是不是注册身份」**。

## 1. 协议

| 项 | 设置 |
|---|---|
| 载波 | `design_searched_realgeom.npz`（B=8，η=1e4） |
| key 空间 | **256**（= 2^8，即 payload 空间；ours-B 的上限就是 2^B） |
| 注册身份数 | **20**（脚本每张测试图对应一个注册 payload） |
| 未注册负样本 | 20 个注册表之外的 payload |
| 划分 | 校准 = prompt 0–19，测试 = prompt 500–519（互不相交） |
| 攻击 | clean / rot45 / rot75；搜索网格 2° |
| 阈值 | FPR 目标 1%，取自校准划分的顺序统计量 |

> 口径提醒：`key 空间 256` 与 `注册量 20` 是两个不同的数，表中分列。
> 由于 ours 的身份 = payload 精确匹配，**Id-Acc 本质上等于 PMR**（不是独立能力），
> 不可与 SFWMark 的 2048-key Id-Acc 直接换算或宣称「追平/胜出」。

## 3. 读数

1. **闭集身份可读取**：20 个注册 payload 在 256 的 key 空间里被全部正确识别，
   且旋转 45°/75° 下不退化（**payload 匹配 margin** 从 190.6 降到 35–44，仍远大于 0）。
2. **但开放集拒绝不行**：在 null 标定的阈值下，未注册 payload 的图像有 30–70% 被
   当成某个注册身份接受。原因是水印本身**合法且可读**，只是 payload 不在注册表里，
   而当前判据只看「与已注册码字的匹配 margin 有多大」，没有「像不像注册表」的绝对标准。
3. **正确做法**：把「未注册 key」当作**标定负样本**，用它（而不是无水印图）定
   拒绝阈值，并把请求的 `fpr` 写成**未注册类上的 FPR**；
   `run_identity_benchmark.py` 已经同时给出这两列
   （`fpr_realised_null` 与 `fpr_realised_unregistered`），
   正式版必须报后者。这与 controls 的处方**形状相同、统计量不同**（见顶部更正）。

## 4. 一次被作废的运行（复现时必看）

第一版把**冒烟（`--N 2`，注册表 2 个 key）**与**正式跑（`--N 20`，注册表 20 个 key）**
写进了同一个 `--out_dir`。`ResumeLog` 按 `uid` 去重，于是图片 0/1/500/501 保留了
冒烟时的 2-key 记录，**同一次「运行」里混进了两种注册表大小**（校验：
`n_keys_registered` 取值同时出现 2 与 20）。
污染目录已改名为 `runs/identity_ours_CONTAMINATED_mix`，本文用的是重跑后的
`runs/identity_ours_n20`（校验：360 行全部 `n_keys_registered = 20`）。

**教训**：冒烟与正式跑必须用不同的 `out_dir`；`ResumeLog` 的续跑是优点，
但也会把旧配置的行静默留下。建议在 `run_config.json` 里加一个「参数指纹」并在
启动时与已有 `rows.jsonl` 的指纹比对，不一致就直接报错。
